# 控制台、统计、悬浮窗与屏保

Android 宿主把「控制」和「显示」分开了：控制台负责配置，悬浮窗负责随手操作，屏保负责在不看屏幕时省电与防烧屏。

<Figure caption="设置页：外观、下载源、权限、保活与屏保开关。截图来自 Android 仓库。" />

| 页面 | 内容 |
| --- | --- |

| 统计 | 原生八类报表、资源管理与 CSV 导出 |

主页右上角的绑定按钮可以直接进入远程 AP 配对，不需要先部署本机 Runtime。

## 原生统计与资源管理

在 AzurPilot 页面的「总览」中打开「统计」，进入 Android 原生统计模块。报表按当前选中的 Runtime 实例隔离；相应任务尚未运行时，该类别可能显示暂无数据。

### 八类报表

| 分类 | 内容 |
| --- | --- |
| 资源趋势 | 资源数量与变化趋势 |
| 大世界趋势 | 大世界行动相关趋势 |
| 大世界总结 | 大世界资源与任务汇总 |
| 委托收益 | 委托奖励统计 |
| 舰船经验 | 舰船经验产出 |
| 大世界掉落 | 大世界掉落物统计，可按任务筛选 |
| 科研掉落 | 科研掉落统计，可按期数或心智 / 物资视图查看 |
| 仓库物品 | 仓库物品统计，可主动运行仓库统计任务 |

报表按类别提供指标卡、趋势曲线、表格和备注。趋势范围可选 1、7、30、90 或 365 天；大世界报表可按月份查看，科研报表可按期数或心智 / 物资切换。大世界掉落支持任务筛选。「重新统计」只重算本地已记录的领奖数据，不会重新操作游戏。报表可导出 CSV。

### 资源管理

资源管理可按 1、7、30 天或自定义日期范围（最长 366 天）查询，并按资源和任务筛选。页面包含库存汇总、资源流向图和流水明细；库存汇总区分当前库存、区间收入、支出和校准，校准单独列出，不计入任务收支。流水记录会标注已确认、实测、识别或校准等依据，并可导出 CSV。

石油控制可单独启用，并设置 1000–24999 的目标值。当前库存取自最近一次有效库存快照；没有快照时显示为空，不代表库存为 0。

「仓库物品」中的「运行仓库统计」会启动 `StorageStatistics` 采集任务。刷新报表只读取最近一次完整快照，不会自动重新扫描。

::: warning 发布状态
原生统计模块已进入 Android `main`（提交 `7b468fb7`）。截至 2026-11-12，最新公开滚动 APK 仍为 `1.3.196`（2026-11-08），早于该提交；不要据此认定 `1.3.196` 已包含这些页面。
:::

## <DocIcon name="monitor" /> 悬浮窗

基于 FloatingX 的全局浮窗，在任意应用或桌面之上可用：

| 操作 | 效果 |
| --- | --- |
| 单击 | 展开/收起面板 |
| 启动 / 停止 | 控制当前实例 |
| 队列 | 查看调度队列与当前任务 |
| 切换实例 | 在多实例间切换目标 |
| 日志 | 实时滚动最近的运行日志 |

悬浮窗是独立 Window，读不到 Activity 的 `Configuration` 或 `ViewModelStore`。它通过 `AppThemeState` 与 `OverlayController` 获取状态，所以主题切换后浮窗会跟着变，但不会共享页面的临时状态。

::: tip 悬浮窗不显示
检查「悬浮窗」权限是否授予。部分厂商 ROM 还有单独的「后台弹出界面」开关。
:::

## <DocIcon name="eye" /> 屏保（防烧屏）

后台运行时屏幕长期点亮，OLED 设备有烧屏风险。屏保提供：

| 行为 | 参数 |
| --- | --- |
| 背景 | 黑色低亮度 |
| 进入方式 | 手动开启，或任务启动时自动进入 |
| 漂移 | 无操作 30 秒后，每 10 秒上下移动 16dp |
| 退出 | 向右拖动解锁条到末端并松手 |

漂移是周期性小幅位移，不会影响游戏画面（屏保覆盖在虚拟屏之上，游戏仍在后台运行）。LCD 设备同样可用，只是收益不如 OLED 明显。

## <DocIcon name="box" /> 桌面小组件

支持 Glance / RemoteViews 小组件，可显示运行状态并快速启停。

部分旧版厂商系统不能可靠解析 `?attr` 矢量着色与 `cornerRadius`，因此小组件使用显式 drawable 资源，不依赖主题属性。

## <DocIcon name="zap" /> 保活

后台运行最容易受到系统省电策略影响。宿主提供三层：

1. **前台服务**：Runtime 或虚拟屏活跃时保进程，通知栏常驻。
2. **多路径保活**：`KeepAliveManager` 按设置启用多条路径，可重复启停，设置开关是最终裁决。
3. **电池优化白名单**：需要你手动授权。

建议同时设置：

- 系统设置 → 电池 → 应用 → AzurPilot → 不受限制。
- 厂商的「自启动」「后台运行」白名单。
- 关闭「省电模式」对后台的限制。

::: warning 保活不是万能的
部分 ROM 会在极端省电或内存压力下强杀进程。这时任务会中断，Runtime 需要重新启动。把日志导出后能看出是被系统杀死还是自身崩溃。
:::

## <DocIcon name="scroll" /> 日志

三路日志分开归档：

| 日志 | 位置 | 内容 |
| --- | --- | --- |
| 宿主日志 | 应用私有目录 | Compose、网关、部署、更新 |
| Runtime 日志 | `proot/session.log` + 上游 `log/` | 调度器与业务 |
| 特权启动链 | 独立时间线 | ADB 启动、Binder 回投、虚拟屏 |

特性：

- 异常时自动保存当前画面快照。
- 默认 7 天轮转，过期清理。
- 一键打包导出为 zip。

导出前确认压缩包里没有 `config/deploy.yaml`、`password.txt`、`remote-access.json`。这些文件在 Runtime 的 `config/` 下，导出日志时不会自动包含，但手动打包整个目录时会。

## 提交机型兼容性报告

在「设置 → 提交你的机型」检查自动采集的机型、系统与运行模式信息，**亲自选择「可正常使用」或「无法正常使用」**，同意公开到 GitHub 后提交。报告会作为评论追加到 [Android 机型支持 Issue #1](https://github.com/wess09/AzurPilot-for-Android/issues/1)，不会新建 Issue。重复报告会关联已有评论；未明确选择实际结果时提交按钮禁用，服务端也会直接拒绝未经实际验证的提交。

该功能严格去敏，不收集 IMEI、序列号、Android ID、MAC、电话状态、日志或截图；提交前仍请在界面上核对显示的信息。

### 提交网络与凭据说明

- **公网 API 地址**：提交请求发送至部署于腾讯云 Docker 服务的 `https://afa-api.azurpilot.com/v1/device-reports`。
- **正文签名防护**：客户端使用内置私钥对请求进行 SHA256withRSA 签名（携带 5 分钟有效期时间戳与 32 字符随机 nonce 防重放）。
- **凭据要求**：签名凭据由 GitHub Actions 在构建发布版时注入（`AZURPILOT_DEVICE_REPORT_*`）。本地自行编译的未注入凭据 Debug 包在打开此页面时会提示功能不可用，属正常现象。
- **真机验证边界**：静态代码与单元测试仅验证数据采集与格式去敏；真实的评论提交依赖服务端在线与 GitHub API 连通，请确保在联网且测试过核心功能后再行提交。

详细字段规范、去敏规则与服务端 Docker 部署见[设备上报技术文档](https://github.com/wess09/AzurPilot-for-Android/blob/main/doc/device-reporting.md)；Android Runtime 工作原理见[开发文档](/android/developer/runtime)。

## <DocIcon name="message" /> 常见问题

| 现象 | 原因 |
| --- | --- |
| 浮窗点击无反应 | 悬浮窗权限被回收，或省电策略限制后台 |
| 屏保不漂移 | 系统关闭了动画（开发者选项），或处于省电模式 |
| 小组件显示旧状态 | 启动器缓存，重新添加小组件 |
| 息屏后任务停止 | 电池优化未放行 |
| 日志导出为空 | 日志已轮转清理，或导出目录无权限 |
