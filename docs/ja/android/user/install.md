# インストールとアーキテクチャ選択

Android 版で特に誤認しやすいポイントが2点あります：**CPU アーキテクチャ**と**完全版 / 軽量版パッケージ**の選択です。選定を誤ると、「インストールは成功したが Runtime が起動しない」または「無駄に 1 GB のダウンロードが発生する」原因になります。

## <DocIcon name="clipboard" /> 1. アーキテクチャの確認

| アーキテクチャ | 代表的なデバイス | 概要 |
| --- | --- | --- |
| `arm64-v8a` | ほぼすべてのスマートフォン・タブレット | 最優先の選択肢 |
| `x86_64` | PC 上の Android エミュレーター、一部の x86 タブレット | MuMu 等のエミュレーター環境で使用 |

確認方法：

- 設定 → 端末情報 → プロセッサ等で `arm64-v8a` と表記されているか確認。
- または任意のデバイス情報確認アプリで `ABI` を確認。
- エミュレーター環境ではインスタンス作成時にアーキテクチャを確認し、x86_64 を選択。

::: danger 32ビット端末の非サポート
Runtime は 64 ビット Linux バイナリに依存しています。`armeabi-v7a` などの 32 ビット専用端末では動作せず、互換フォールバックもありません。
:::

## <DocIcon name="package" /> 2. パッケージ種別の選定

| パッケージ | 容量規模 | 初回起動時の動作 | どのような場合に使うか |
| --- | --- | --- | --- |
| 完全版 APK | 大（rootfs 内包） | ローカルで 1〜3 分で展開完了（**通信不要**） | 初めて導入する場合 |
| 軽量増分 APK | 小（rootfs なし） | 初回起動時に約 1 GB の Runtime をダウンロード | すでに完全版を導入済みで、ホストのみ更新する場合 |

初回インストール時は必ず完全版パッケージを選択してください。軽量版の利点はホスト側の更新にあります。上書きインストールしても Runtime が再展開されることはなく、設定やインスタンスはそのまま保持されます。

## <DocIcon name="download" /> 3. ダウンロード

| 配布チャネル | アドレス | 適用環境 |
| --- | --- | --- |
| GitHub Releases | `github.com/wess09/AzurPilot-for-Android/releases/latest` | 国際ネットワーク環境 |
| CNB | `cnb.cool/azurpilot/AzurPilot-for-Android/-/releases` | 中国本土ネットワーク環境（新規インストール時のデフォルト） |

両チャネルで配信されているマニフェストおよび添付ファイルは同一のリビジョンであり、ファイルサイズおよび SHA-256 は一致します。アプリ内の設定画面からダウンロードソースを切り替えることも可能です：

| ソース指定 | 概要 |
| --- | --- |
| `cnb` | 中国本土向け直連（デフォルト） |
| `direct` | GitHub 公式への直接接続 |
| 内蔵ミラー | ghproxy 形式の5つのプレフィックス |
| カスタム | ghproxy 形式のプレフィックスを手動入力（不正入力時は直連へフォールバック） |

::: tip 利用不可なミラーについて
内蔵リストのうち `gh-proxy.net` は JavaScript 実行機能を持たないダウンローダーに対して CAPTCHA チャレンジ画面を返却するため、**ダウンロードには使用できません**。実測で比較的安定しているのは `gh.ddlc.top`、`ghfast.top` です。ソースを切り替えてもバージョンや検証値は変わりません。
:::

## <DocIcon name="smartphone" /> 4. インストール手順

<Steps>
<Step title="提供元不明のアプリの許可">

システムから「提供元不明のアプリのインストールは禁止されています」と警告された場合は、設定でファイルマネージャーやブラウザに対してインストールの権限を許可してください。

</Step>
<Step title="署名衝突（競合）の解決">

過去に別の署名鍵でビルドされた APK（自己ビルドした debug パッケージなど）をインストールしていた場合、上書き時に `INSTALL_FAILED_UPDATE_INCOMPATIBLE` が発生します。この場合は既存アプリのアンインストールが必要です——**アンインストールすると Runtime や設定を含むアプリデータが全消去される**ため、事前に設定とログをエクスポートしてください。

</Step>
<Step title="インストールと初回起動">

インストール完了後、アプリを開きます。初回起動時はまず権限付与の案内画面が表示され、その後に Runtime のデプロイ画面へ遷移します。

</Step>
<Step title="Runtime 展開の待機">

完全版：展開処理に 1〜3 分かかります。
軽量版：約 1 GB のダウンロードが行われた後に展開されます（Wi-Fi 環境を強く推奨）。

</Step>
</Steps>

## <DocIcon name="circle-check" /> 5. インストール結果の確認

| チェック項目 | 期待される状態 |
| --- | --- |
| ホーム画面の Runtime 状態 | `Ready` / 準備完了 |
| ストレージ消費量 | 約 1.5〜2.5 GB 増加 |
| 周回画面 | 画面の映像ストリームが表示可能（権限アクティベート後） |
| コンソール | 内蔵 WebUI が正常に表示される |

ステータスが `Failed` で停止した場合は、エラー詳細を開いて `reason` を確認してください：

| エラー状態 | 主な原因 | 対処方法 |
| --- | --- | --- |
| `NotBundled` | 軽量版を使用しているが、Release 上に当該アーキテクチャの Runtime が存在しない | 完全版 APK をダウンロード |
| `LowDisk` | 空きストレージが 2 GB 未満 | 不要なデータを削除して容量を確保 |
| `Downloading` で停止 | ネットワーク不調、またはミラーのアクセス拒否 | ダウンロードソースを変更 |
| `Failed` | ハッシュ検証失敗、または展開時の異常中断 | 再試行。解決しない場合は再ダウンロード |

## <DocIcon name="circle-off" /> 6. アンインストールとデータ管理

アプリをアンインストールすると以下のデータがすべて消去されます：

- Runtime（`rootfs` ディレクトリ全体）
- すべてのインスタンス設定および統計 SQLite データベース
- ログおよびスクリーンショット記録

クラウド同期は行われません。データを保持したい場合は、事前にアプリ内のエクスポート機能を利用するか、ADB 経由でバックアップを取得してください。

## <DocIcon name="message" /> よくある質問

| 現象 | 主な原因 |
| --- | --- |
| インストール時に「パッケージの解析エラー」 | ダウンロードファイルの破損、またはアーキテクチャ不一致 |
| インストール後に起動直後クラッシュ | アーキテクチャ不一致（ARM 端末に x86 パッケージを導入など） |
| Runtime が `Downloading` のまま進まない | ミラーのアクセスブロック、プロキシによる遮断 |
| 展開後の初回 WebUI 表示が著しく遅い | 正常な動作：`__pycache__` 再構築のため初回は90秒以上かかる場合があります |
| 上書きインストール後に設定が消えた | 署名不一致により OS が内部でアンインストール＆新規導入を実行したため |
