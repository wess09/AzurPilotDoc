# タスク一覧

コアプログラムのスケジューリング可能な各機能は、すべて固有の**タスクコマンド**に対応しています。コマンドは英字識別子（例：`OpsiHazard1Leveling`）であり、WebUI 上では表示名（例：「侵食1レベリング」）として描画されます。

以下のテーブルは `module/config/argument/args.json`、`module/config/i18n/*.json`、`task.yaml` に基づいて自動生成されており、直接インクリメンタル検索が可能です。

## <DocIcon name="clipboard" /> 全タスク共通の基本構造

すべてのタスクは共通のスケジュール設定を持っており、タスク設定画面の最上部にある「スケジューラー設定」に配置されています：

| 設定項目 | 意味と機能 | デフォルト値 |
| --- | --- | --- |
| この機能を有効化 | スケジューラーの実行キューに含める | オフ |
| 通知プッシュ | タスク終了時に結果を外部通知 | オフ |
| 次回実行時刻 | この時刻を迎えると実行可能となる | 2020-01-01（即座に実行） |
| 成功時の遅延分数 | 正常終了後のインターバル間隔（分） | タスク固有値 |
| 失敗時の遅延分数 | エラー終了後のインターバル間隔（分） | 120 |
| サーバー更新時刻 | 日次タスクの基準リセット時刻 | 00:00 |
| センシティブタスク | エラー発生時に再起動せずプロセス停止 | 一部の大世界タスクで有効 |

これに加え、各タスクには専用の設定グループが用意されています。マニュアルでは**動作結果に大きな影響を与える重要なパラメータ**を中心に解説しています。

## <DocIcon name="eye" /> タスクマニュアルの読み方

各タスクの解説は以下の構成で統一されています：

1. **機能概要**：どのような自動操作を行い、何が得られるか。
2. **前提条件**：必要なアンロック段階、編制要件、燃料消費の有無。
3. **主要設定**：海域選択、条件分岐、資材消費の可否。
4. **推奨構成**：そのままコピーして利用できる標準設定値。
5. **動作検証**：タスク完了後にどこを確認して成功と判定するか。
6. **制約事項**：特定サーバーや環境における注意事項。

## <DocIcon name="lightbulb" /> 初心者向けの推奨スタート構成

新規導入直後は、まず以下の低リスクなタスクのみを有効化して数日間稼働させることを推奨します：

```text
Restart           # 日次自動再起動（メモリリーク防止）
Reward            # 一括回収
Commission        # 委託
Research          # 研究（科研）
Dorm              # 寮舎
Daily             # デイリー任務
```

ログにエラーの繰り返しが発生しないことを確認した上で、通常出撃、イベント海域、セイレーン作戦を順次有効化してください。大世界やイベント周回は設定項目が多岐にわたるため、初期導入初日に行うことは推奨されません。
