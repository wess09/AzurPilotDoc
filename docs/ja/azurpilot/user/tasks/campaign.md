# 出撃とイベント

出撃系タスクは燃料（石油）を消費し、リターンとリスクの振れ幅が最も大きいカテゴリです。設定前に以下の3点を明確にしてください：**「どの海域を周回するか」「どのような条件で周回を停止するか」「どの艦隊を使用するか」**。

## <DocIcon name="clipboard" /> 共通の引数グループ構造

すべての出撃タスクは以下の3つのパラメータグループを共有します：

| グループ名 | 主要フィールド | 役割 |
| --- | --- | --- |
| `Campaign` | `Name`、`Mode`、`UseAutoSearch`、`Use2xBook`、`AmbushEvade` | 海域番号、難易度、自律戦闘、2倍作戦書、伏撃回避 |
| `StopCondition` | `OilLimit`、`CoinLimit`、`RunCount`、`MapAchievement` | 周回の終了条件（回数、燃料、資金等） |
| `Fleet` | `Fleet1`、`Fleet1Formation`、`FleetOrder` | 出撃艦隊の指定、陣型、出撃順序 |

停止条件の実際の判定ロジック：保有燃料が `max(OilLimitHardFloor, OilLimit)` を下回った場合に周回を停止します。ハード下限値はデフォルトで 500 に設定されており、燃料が完全に枯渇してデイリー任務が消化できなくなる事態を防ぎます。

::: tip 初回は手動でクリアしてください
新海域やイベント海域をスクリプトで周回する前に、ゲーム内で手動で一度クリアし、自律検索（自律尋敵）機能をアンロックしておくことを推奨します。スクリプトによるマップ攻略は画面認識に依存するため、新ギミック（ワープマス、特殊ギミック、特殊ボス等）が存在する場合は手動での先行クリアが必要です。
:::

## <DocIcon name="target" /> メイン海域 1 / 2 / 3

メイン海域向けに独立した3つのタスクスロットが用意されており、「異なる海域・異なる艦隊・異なる終了条件」の組み合わせを並行して定義できます。

| 項目 | 詳細 |
| --- | --- |
| 用途 | レベリング、設計図集め、資金稼ぎ、好感度上げ |
| 前提条件 | 対象海域がアンロック済みであること。ゲーム内で複数艦隊が編成可能であること |
| 主要設定 | `Campaign.Name`（例：`12-4`）、`Mode`（`normal`）、`UseAutoSearch`（有効化） |
| 推奨設定 | 12-4 レベリング：`UseAutoSearch=true`、`AmbushEvade=true`、`StopCondition.OilLimit=1000` |
| 動作検証 | ログに「海域突入 → 自律尋敵 → リザルト」が出力され、経験値と資金が増加すること |
| よくある失敗 | 「敵艦探索中」で停止する場合はマップ認識失敗の疑いあり。`UseClearMode` の確認または手動で1回クリア |

`DefeatWithdraw` 設定により敗北時の挙動を制御できます：`withdraw_stop`（撤退してタスク終了）、`switch_fleet`（別艦隊に切り替えて継続）、`withdraw_continue`（撤退後に再度挑戦）。

## <DocIcon name="zap" /> 緊急委託周回（`GemsFarming`）

| 項目 | 詳細 |
| --- | --- |
| 用途 | 特定海域を高速周回してダイヤが獲得可能な緊急委託を発生させつつレベリング |
| 前提条件 | 海域アンロック済み、低燃費艦隊の準備 |
| 主要設定 | `GemsFarming.Fleet1`、`Campaign.Name`、`StopCondition` |
| 制限事項 | **低燃費3油周回（ThreeOilLowCost）と排他関係**にあり、同時に有効化できません |
| 動作検証 | 委託一覧に緊急委託が出現し、ログに委託検出と撤退が記録されること |

## <DocIcon name="badge-dollar" /> 低燃費3油周回（`ThreeOilLowCost`）

消費燃料 3 の極小編成で低難度海域を周回し、旗艦が Lv 32 に達した時点で自動的に旗艦を交代・退役させます。

| 項目 | 詳細 |
| --- | --- |
| 用途 | 燃料消費を極限まで抑えた長時間の資材・ドロップ艦船集め |
| 前提条件 | 育成済み低燃費艦船の所持。[一括退役設定](/ja/guide/requirements#一括退役)が正しく構成されていること |
| 主要設定 | `Campaign.Name`（通常は 1-1 等）、`StopCondition.RunCount` |
| 制限事項 | 緊急委託周回と排他。退役設定が不適切だと誤退役のリスクあり |
| 動作検証 | 燃料消費が極めて緩やかであり、退役ログに Lv 32 の旗艦が記録されること |

## <DocIcon name="shield" /> 1-1 伏撃周回（`Ambush11`）

1-1 においてボスを倒さず伏撃（待ち伏せ）のみを繰り返し発生させて資金を稼ぎます。

::: warning 実験的機能
機能名に未完成フラグが付与されています。収益効率は伏撃の発生確率に左右され、仕様変更の影響を受けやすいため、主力の稼ぎ手段としては推奨されません。
:::

## <DocIcon name="star" /> イベント海域 1 / 2 / 3

| 項目 | 詳細 |
| --- | --- |
| 用途 | 期間限定イベント海域の周回（イベント PT、限定ドロップ艦、設計図の収集） |
| 前提条件 | イベント海域が開催中であること。通常難易度が一度クリアされていること |
| 主要設定 | `Campaign.Event`（対象イベント名）、`Campaign.Name`（海域指定）、`StopCondition`（目標 PT または周回数） |
| 推奨設定 | まず `RunCount=1` で入場できることを確認してから周回数を拡大 |
| 動作検証 | イベント PT が増加し、ログに正しい海域番号が表示されていること |
| 制限事項 | 共闘形式のイベントは別タスク（`Raid`）を使用してください |

3つのスロットにより、「イベント海域で PT を稼ぎつつ、通常海域でレベリングを行う」といった柔軟な多面待ちスケジュールが可能です。

## <DocIcon name="megaphone" /> 共闘イベント（`Raid` / `RaidScuttle`）

| タスク | 用途 | 留意点 |
| --- | --- | --- |
| `Raid` | 共闘イベントの通常出撃 | 全体ボス HP が共有されるイベントに対応 |
| `RaidScuttle` | 共闘での自沈周回 | 早期撃沈されることで高速に周回数や好感度を稼ぐ特殊設定 |

共闘における「自沈」は失敗ではなく、あえて低戦力艦隊を即座に戦闘不能にさせて短時間で回数をこなす戦術です。仕様を十分に理解した上で利用してください。

## <DocIcon name="sparkles" /> イベント専用特殊タスク

| タスク | 対象イベント | 説明 |
| --- | --- | --- |
| `Hospital` | 深谷来信 | イベント専用の独自操作フロー |
| `Coalition` | 連合作戦 | 複数艦隊が連携する連合イベント |
| `CoalitionScuttle` | 連合自沈 | 連合作戦での好感度稼ぎ用自沈フロー |
| `MaritimeEscort` | 海上護衛 | 輸送船団を護衛するミニゲーム形式の海域 |
| `EventShop` | イベントショップ | 優先度設定に基づきイベント PT をアイテムへ交換 |
| `CoalitionSp` | 怪談紀実 SP | 特定イベントの SP 海域専用 |

これらのタスクは対応イベント開催期間中のみ動作します。イベント終了後はエントリーが見つからずエラーまたはスキップとなります。

## <DocIcon name="file" /> 作戦履歴（`WarArchives`）

| 項目 | 詳細 |
| --- | --- |
| 用途 | 過去のアーカイブイベント海域のデイリー挑戦回数の消化とドロップ狙い |
| 前提条件 | 作戦履歴の対象海域がアンロック済みであること |
| 主要設定 | `WarArchives.DailyRunCount`、`AutoClear`、`AutoClearTarget` |
| 制限事項 | 自律尋敵が利用可能な状態で運用してください |
| 動作検証 | 作戦履歴の残り挑戦回数が減少し、ドロップ統計に記録されること |

## <DocIcon name="calendar" /> デイリー海域 A / B / C / D / SP

| タスク名 | 対象海域 | 運用方法 |
| --- | --- | --- |
| `EventA` 〜 `EventD` | デイリー A/B/C/D 海域 | 毎日のボーナスポイント回収用（1日1回出撃） |
| `EventSp` | デイリー SP 海域 | 前提海域のクリアが必要。1日1回限定の高難度 |
| `RaidDaily` | 共闘デイリー | 共闘イベントのデイリー特別挑戦回数の消化 |

これらのタスクは `Scheduler.ServerUpdate`（サーバーリセット時刻）が重要です。回数は日付変更時にリセットされるため、リセット直後に実行されるようスケジュールしてください。

## <DocIcon name="refresh" /> イベント対応の季節性について

イベント海域のマップ構造やギミックは毎月刷新されます。`campaign/` 配下には Python によるマップ定義コードが配置されています。新イベントへの対応にはソースコードの更新が必要となるため：

- イベント開幕直後はスクリプトの対応パッチが公開されるまで待機してください。
- ギミックの大幅な仕様変更により画面認識が失敗する場合があるため、初回はログを監視してください。
- 過去イベントの設定をそのまま新イベントに無理に適用しないでください。

## <DocIcon name="hand" /> 停止条件（StopCondition）の指定方法

| 周回目的 | 設定すべきフィールド |
| --- | --- |
| 指定回数周回して停止 | `RunCount = N` |
| 燃料が一定値を下回ったら停止 | `OilLimit`（ハード下限 500 と併用） |
| 獲得資金が目標に達したら停止 | `CoinLimit` |
| 海域脅威度ゼロ（100% 達成）で停止 | `MapAchievement = 100_percent_clear` |
| 海域の星3達成で停止 | `MapAchievement = map_3_stars` |
| 艦船が指定レベルに到達したら停止 | `ReachLevel` |
| 新規未所持艦船がドロップしたら停止 | `GetNewShip = true` |

`StageIncrease` を有効にすると、目標条件を達成した際に自動的に次の海域（例：12-1 → 12-2）へ進撃します。

## <DocIcon name="wrench" /> 動作検証とトラブルシューティング

タスク完了後の確認チェックリスト：

1. ログに「海域突入 → 戦闘開始 → 勝利リザルト → 撤退 / 次戦へ」の一連の流れが出力されているか。
2. 統計画面で出撃回数と消費燃料が正しく加算されているか。
3. ゲーム内で海域の進行度や PT が増えているか。

よくあるトラブル：

| 現象 | 主な原因 |
| --- | --- |
| 海域選択画面でループする | 海域番号の入力ミス、または対象海域が未開放 |
| 海域に入ったあと動かない | 自律検索が未アンロック、または `UseAutoSearch` が無効 |
| 頻繁に撤退を繰り返す | 艦隊の戦力不足により `DefeatWithdraw` がトリガーされた |
| 燃料消費が異常に激しい | 意図しない大型艦隊や潜水艦隊が出撃している |
| イベント海域の認識に失敗する | コアプログラムのリソースが最新イベントに未更新 |
